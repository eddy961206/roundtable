# 디자인 브리프 — Roundtable UI v2

작성: 2026-10-17. 대상: UI 담당 에이전트(Gemini 4 Argon)와 리뷰어(Codex GPT-6.1 Sol, Claude Opus 5.5).
이 문서는 "무엇을 왜"를 정한다. "어떻게"는 담당자가 정하되, 아래 수용 기준과 검증 방법으로 판정한다.

## 1. 사용자와 과업 (Jobs To Be Done)

사용자: 혼자 일하는 개발자 1명. Claude Code·Codex·Antigravity를 모두 구독한다. Go·VMS 도메인은 아직 배우는 중이다.
화면을 계속 띄워 두고, 다른 일을 하다가 힐끗 보고, 필요할 때만 끼어든다.

| # | 상황 | 하고 싶은 일 | 성공의 모습 |
|---|---|---|---|
| J1 | 세 에이전트에게 같은 문서를 던졌다 | 누가 무엇을 하고 있는지 3초 안에 파악한다 | 참가자별 상태·현재 도구·경과 시간이 한 줄로 보인다 |
| J2 | 한 에이전트가 엉뚱한 방향으로 간다 | 그 에이전트에게만 즉시 방향을 바꾸라고 말한다 | 대상 지정 → 전송 → "즉시 주입됨 / 다음 턴 전달" 결과가 분명히 보이고, 다음 메시지는 자동으로 전체 대상으로 돌아온다 |
| J3 | 대화가 길어졌다 | 토큰을 너무 쓰고 있는지, 한도에 걸릴지 판단한다 | 공급사별 5시간·주간 남은량, 방 누적 토큰, 최근 소모 속도, 컨텍스트 사용률이 한 영역에서 보이고 임계치에서 경고한다 |
| J4 | 답이 이상하다 | 그 답이 어떤 도구·서브에이전트를 거쳐 나왔는지 확인한다 | 답 아래에서 도구 호출과 서브에이전트 대화가 시간순·중첩으로 보이고, 진행 중에도 실시간으로 자란다 |
| J5 | 결정을 내려야 한다 | 세 의견의 차이를 비교한다 | 토론 라운드·신호(CONTINUE/AGREE/PASS/CONCLUDE)가 눈에 띄고, 내보내기로 문서화할 수 있다 |
| J6 | 처음 켰다 | 무엇을 할 수 있는지 1분 안에 이해한다 | 빈 상태 화면에 @멘션·조정·토론·권한 모드 설명과 예시 프롬프트가 있다 |

## 2. 설계 원칙 (Nielsen 10 휴리스틱에서 이 제품에 중요한 것)

1. **시스템 상태의 가시성** — 실행 중·대기·오류·중단을 색만이 아니라 아이콘+문구로 표시한다. 긴 작업에는 경과 시간을 보인다.
2. **실제 세계와의 일치** — 용어를 통일한다: "조정(steering)", "작업 기록", "서브에이전트", "한도", "컨텍스트".
3. **사용자 통제와 자유** — 중지는 언제나 한 번에 닿는 곳. 대상 지정은 1회성이고 Esc로 해제된다.
4. **일관성** — 같은 정보는 한 곳에서만 원본으로 보인다. 중복 표시는 요약이어야 하고 원본으로 연결된다.
5. **오류 예방** — 꺼진 참가자를 멘션하면 입력 중에 경고한다. 위험한 모드(write)는 시각적으로 구분한다.
6. **기억보다 인식** — 멘션 자동완성(방향키·Enter·Tab), 참가자 칩, 모델·노력 선택이 눈에 보인다.
7. **유연성과 효율** — 키보드 단축키: Enter 전송, Shift+Enter 줄바꿈, Esc 대상 해제·팝업 닫기, Ctrl+. 모두 중지, `/` 입력창 포커스.
8. **미니멀 디자인** — 진행 중이 아닌 정보는 접는다(점진적 공개). 기본 화면은 대화가 주인공이다.
9. **오류 인식·진단·복구** — 실패한 턴에는 원인 문구와 "다시 시도" 버튼(같은 에이전트에게 직전 사용자 메시지 재요청).
10. **도움말** — 빈 상태와 툴팁으로 충분히. 별도 도움말 페이지는 만들지 않는다.

## 3. 정보 구조

- **왼쪽**: 방 목록(검색), 새 방.
- **가운데**: 방 머리(제목·모드·작업 폴더·동작 버튼) → 사용량 대시보드 띠(J3) → 타임라인 → 토론 상태 → 입력창.
- **오른쪽**: 참가자 카드(켜기/끄기, 모델, 추론 노력, 상태·현재 도구·경과 시간, 컨텍스트 게이지, 해당 공급사 5시간·주간 남은량, 이 방 누적 토큰) → 대기열.
- 좁은 화면(≤1100px)에서는 오른쪽을 서랍으로, ≤760px에서는 왼쪽도 서랍으로.

## 4. 사용량 대시보드 띠 (J3 — 사용자가 가장 강조한 요구)

공급사별 칩 1개씩 + 방 합계 칩 1개.
- 공급사 칩: 이름 · 5시간 남은 % 미니 게이지 · 주간 남은 % 미니 게이지 · 리셋까지 남은 시간(툴팁).
- 방 합계 칩: 입력·출력 토큰 합계, 비용(아는 공급사만), **최근 10분 소모 속도(토큰/분)**.
- 경고: 남은 한도 ≤15% 또는 컨텍스트 ≥80% 또는 한 턴 입력이 15만 토큰 이상이면 칩이 경고색+아이콘으로 바뀌고 이유를 툴팁으로 보인다.
- 데이터가 없는 공급사는 "아직 관측 안 됨"으로 표시한다(빈칸 금지).

## 5. 데이터 계약 (백엔드가 제공, UI는 이것만 쓴다)

- `GET /api/providers` → `{providers:[{id,label,available,can_steer,models:[{id,label}],efforts:[...],model_efforts:{<modelID>:[...]},default_model,default_effort}], limits}`.
  **추론 노력 목록은 모델마다 다를 수 있다**: `model_efforts[model]`이 있으면 그것을, 없으면 `efforts`를 쓴다. 모델을 바꾸면 노력 목록을 다시 그리고, 현재 값이 목록에 없으면 목록의 마지막에서 두 번째(보통 high)로 맞춰 PATCH 한다.
- `limits[providerID] = {provider, at, windows:[{label, used_percent, resets_at}], plan, credits, note}` — `used_percent`는 **사용량**이다. 남은량은 100-used로 계산해 표시한다. agy(Gemini)도 같은 형식으로 들어온다.
- 메시지 `usage`: `input_tokens, output_tokens, cache_read_input_tokens|cached_input_tokens|cache_read_tokens, context_tokens, total_cost_usd`.
- 참가자: `status(idle|queued|running), status_text, totals{input,output,cached,cost_usd,turns}, context_tokens, context_window, model, effort, enabled`.
- SSE 이벤트 종류: `message, delta, trace, participant, queue, discussion, limits, room`.

## 6. 시각 디자인

- 디자인 토큰을 `:root` CSS 변수로 정의하고 다크/라이트 둘 다 지원(`prefers-color-scheme` + 수동 전환, localStorage 저장).
- 공급사 고유색(Claude 주황, Codex 초록, Antigravity 파랑)은 아바타·이름에만 쓰고, 상태색(성공·경고·위험)과 섞지 않는다.
- 간격 4px 배수, 본문 14px, 코드 12.5px, 행간 1.5. 그림자 대신 경계선과 면 대비로 위계를 만든다.
- 애니메이션은 상태 전달용만, `prefers-reduced-motion`에서 끈다.

## 7. 접근성 (WCAG 2.2 AA)

- 본문 대비 4.5:1 이상, 큰 글자·아이콘 3:1 이상.
- 모든 조작을 키보드로. `:focus-visible` 표시. 아이콘 버튼은 `aria-label`.
- 새 메시지·상태 변화는 `aria-live="polite"` 영역으로 알린다(스트리밍 델타마다 읽지 않게 완료 시점에만).
- 랜드마크: `nav`(방 목록), `main`(대화), `aside`(참가자), `form`(입력창).

## 8. 성능 예산

- 프레임워크 없음. app.js+style.css 합쳐 150KB 이하(마크다운 라이브러리 제외).
- 스트리밍 렌더는 메시지당 최대 초당 8회. 메시지 1000개 방에서도 스크롤이 끊기지 않게, 타임라인은 마지막 200개만 DOM에 두고 위로 스크롤하면 더 붙인다.
