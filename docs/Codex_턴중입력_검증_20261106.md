# Codex 턴 중 입력: 결정과 검증

원구현 기록: 2026-11-06, `fix/codex-steer`, 기준 `383e02d`. 사용자가 승인한 범위는 app-server 전환·메시지별 수신 확인·검증·이 브랜치의 커밋까지다. main 병합·push·PR·공유 서버 교체는 포함하지 않는다.

## 결정

- Codex의 실행 경로를 app-server stdio로 교체한다. 프로세스는 기존처럼 rt 턴마다 하나를 띄운다. `exec --json` 실행 경로는 남기지 않는다.
- 세션은 `thread/start`, `thread/resume`, `thread/fork`로 열고 `turn/start`로 시작한다. 입력은 `turn/steer`에 현재 `expectedTurnId`와 rt 메시지 ID(`clientUserMessageId`)를 보낸다.
- 상주 app-server는 필요하지 않았다. 턴마다 실행하면 기존 취소·세션 인계·프로세스 소유 범위를 유지할 수 있다.
- `clientUserMessageId`는 중복 방지 키가 아니다. 설계 실험에서 같은 ID를 두 번 보내자 사용자 입력도 두 번 저장됐다. 응답 유실 뒤에는 프로세스 종료 후 이력을 조회하며, 미수신만 다음 턴으로 넘긴다.
- 완료는 `turn/completed`로 판단한다. 비동기 질문의 `phase=final_answer`나 텍스트 출력은 턴 완료가 아니다.
- 프로토콜 기준은 [공식 app-server 문서](https://learn.chatgpt.com/docs/app-server)와 설치된 Codex 0.166.0의 실측·생성 JSON Schema다.
- app-server 자체가 없으면 실행 오류로 끝낸다. `turn/steer`만 없거나 현재 턴이 이미 끝났으면 원문·이미지를 다음 턴으로 한 번 전달한다.

## 전달 상태

| 저장 상태 | 의미와 화면 |
|---|---|
| `pending` | rt가 입력을 저장했으며 CLI에 쓰기 전. 전송 중 |
| `sending` | 송신 정보를 먼저 저장했으며 수신 응답을 기다림. 전송 중 |
| `accepted` | Codex의 같은 turnId 응답 또는 Claude의 같은 UUID user echo를 받음. 현재 턴 전달됨 |
| `queued` | 미지원·거절·종료 경합 등으로 다음 턴 대기 |
| `delivered` | 다음 턴의 일반 프롬프트에 전달됨 |
| `uncertain` | 송신 결과가 불명확해서 저장된 공급사 이력 조회 중 |
| `failed` | 이력 조회도 실패. 원문·오류 보존, 자동 재전송 없음 |
| `error`·`stopped` | 다음 전달 턴이 오류·취소로 끝남 |

명시적 중단은 `halted`도 저장한다. 재기동 복구가 중단한 일을 다시 시작하지 않는다. 옛 `Live`만 있는 메시지는 변경하지 않고 “현재 턴 전달 · 이전 기록”으로 보인다. 수신 확인은 모델의 이해나 지시 실행 완료를 뜻하지 않는다.

`rt wait`와 `post --wait_seconds`는 메시지의 정확한 rt TurnID를 따른다. 실패한 입력이 after_seq와 같더라도 전달 실패 상태를 결과에 남긴다. 메시지 본문 예산이 작아도 이 상태를 생략하지 않는다. 이력에 대상 TurnID가 없으면 명시적 조회 오류다.

## 남은 범위

- 실제 구형 Codex 바이너리별 검증은 하지 않았다. app-server 부재·steer 미지원은 명시적 실패 주입으로 확인했다.
- Windows elevated 초기화, 실제 원격 PC, 실제 Codex 서브에이전트 실행은 미검증이다. 관련 인자·원격 다음 턴 전달·롤아웃 parser 시험은 포함한다.
- 전달 확인 실패는 중복을 피하려고 자동 재전송하지 않는다. 원문과 오류를 남기는 의도된 한계다.
- 기본 승인 정책은 `never`이며 기존 실행 권한을 유지한다. 지원하지 않는 서버 요청을 무시하거나 자동 승인하지 않는다.
- 8787 반영·main 병합·push·PR은 이 작업 범위 밖이다. 사용자 요청 전달을 포함한 `b4ccd12` 위 재기반 검증은 아래 후속 기록으로 구분한다.


## b4ccd12 위 재기반과 사용자 요청 답변 결합
