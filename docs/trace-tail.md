# 작업 기록 tail 조회

`GET /api/rooms/{id}/trace/{msg}?tail=N`은 마지막 N개 이벤트와 서브에이전트 문맥을 반환한다. N은 1~5000의 정수다. 빈 값, 중복 tail, 범위 밖 값, 잘못된 쿼리 인코딩은 HTTP 400이다.

```json
{"events": [], "total": 0, "truncated": false}
```

- `events`: 마지막 N개 이벤트와 보충 이벤트를 원래 파일 순서로 반환한다. 마지막 N개에 등장한 `parent`마다 창 밖의 `subagent_start`와 가장 최근 `subagent_meta`를 추가한다. 해당 종류가 창 안에 있으면 이전 기록을 추가하지 않는다. 창 밖에서는 종류별 최신 1개만 보관한다. 보충 정보 때문에 배열 길이는 N보다 클 수 있다.
- `total`: 해당 메시지에 저장된 전체 이벤트 개수다. 방의 다른 메시지는 세지 않는다.
- `truncated`: `total > N`이다. 보충 이벤트를 추가하기 전의 창이 잘렸는지를 나타낸다.

`tail`이 없으면 기존 이벤트 배열을 그대로 반환한다. 내보내기와 기존 `ReadTrace` 호출도 전체 기록을 계속 사용한다. 이 변경에는 화면 연결이 포함되지 않는다.

파일 크기를 append 잠금 안에서 확정한 뒤, 잠금을 해제하고 64 KiB 블록 단위로 뒤에서 읽는다. 전체 파일을 메모리에 올리지 않는다. 마지막 N개와 필요한 부모 정보만 보관한다. 단일 행에는 크기 제한을 두지 않는다. 정확한 메시지별 `total`을 세기 위해 파일 전체 I/O는 여전히 필요하다. 잘못된 JSON은 부분 성공으로 숨기지 않고 오류로 반환한다.

## 검증

2026-10-19 KST, Windows / Go 1.27.2에서 확인했다.

- `internal/room/trace_tail_test.go`: 잘림, 창 밖 start와 최신 meta, 창 안 meta 우선, 관련 없는 부모 제외, 여러 메시지가 섞인 파일, 순서, 빈 기록, 창 경계, CRLF, 64 KiB를 넘는 행, 고정 크기 스냅샷, 손상된 기록.
- `internal/server/trace_tail_test.go`: 실제 HTTP handler의 응답, N 검증, 쿼리 없는 배열 응답의 바이트 단위 불변.
