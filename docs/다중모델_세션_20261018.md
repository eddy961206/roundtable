# 다중 모델 참가자와 원본 CLI 세션

## 변경

기존에는 참가자 ID와 공급사 ID가 같았다. 같은 공급사를 두 번 추가하면 실행 대기열과 세션을 구분할 수 없었다. 이제 참가자마다 고유 ID를 만들고 `provider`에 공급사를 따로 기록한다. 기존 방의 ID와 메시지 작성자는 보존한다.

- 새 방의 반복 구성과 기존 방의 참가자 추가에서 모델별 인원을 지정한다. 한 방의 활성 구성은 최대 32명이다. 같은 모델을 여러 명 추가해도 세션은 별개다.
- `@claude`, `@codex`, `@agy`는 해당 공급사의 활성 참가자 전체를 부른다. 고유 ID 멘션과 대상 조정은 한 명을 부른다.
- 제거한 참가자는 보관 상태가 된다. 과거 메시지의 작성자와 누적 사용량은 유지한다. 공급사 한도는 공유 값이며 참가자별로 합산하지 않는다.
- 입력 오류가 있으면 설정 일부만 저장하지 않는다. 모델·추론 수준 변경은 실행이 끝난 뒤 허용하고 새 세션으로 시작한다. 새 세션에는 이전 자기 답변과 전달된 조정 메시지도 전달한다.
- 모델 정보 조회가 느려도 방 상태 잠금을 잡고 기다리지 않는다. Claude·Codex 스트림 보조 처리의 종료와 상태 접근 경쟁도 정리했다.
- 서버는 로컬 접속과 같은 출처의 브라우저 요청만 허용한다. CLI별 기존 도구·권한 옵션은 유지했다.

## 원본 세션

공식 CLI가 저장한 세션을 그대로 이어 쓴다. 새 답변에는 공급사·세션 ID·절대 작업 폴더·권한 모드·모델·추론 수준을 함께 기록한다. 모델이나 방 설정을 바꿔도 이전 답변의 원본 세션 정보는 바뀌지 않는다.

Windows의 `CLI에서 열기`는 새로운 콘솔에 원래 세션을 연다. Go의 일반 프로세스 실행은 빈 표준 입력을 연결할 수 있어서, Windows 콘솔 입력·출력을 직접 생성하도록 구성했다. 인자는 Windows 규칙으로 인용하고, PowerShell 코드에는 리터럴로 전달한다. Claude의 빈 `--tools` 인자도 유지한다.

현재 세션을 CLI로 열면 참가자를 비활성화한다. 창이 닫히기 전에는 같은 세션을 다시 열거나 Roundtable에서 다시 실행할 수 없다. 다른 과거 세션을 열 때는 현재의 별도 세션을 비활성화하지 않는다. 명령 복사와 서버 재시작을 넘는 외부 창 추적은 자동 관리 대상이 아니다.

## 직접 확인한 범위

2026-10-18, Windows에서 별도 서버와 데이터 폴더로 확인했다. 테스트 파일을 생성하거나 테스트 모음을 실행하지 않았다.

## 한계

- Opus·Fable는 목록·설정 동작만 확인했다. 실제 Claude 호출은 Haiku 5.5만 사용했다. Gemini 호출은 3.8 Flash만 사용했다.
- 공급사 데스크톱 앱의 목록 동기화와 원본 CLI에서 작성한 새 메시지의 Roundtable 역수입은 구현 범위가 아니다. 원본 CLI는 최초 폴더 신뢰 확인을 표시할 수 있다.
- 기존 기록에는 과거 작업 폴더가 없을 수 있다. 출처가 불명확한 과거 폴더를 추정해 열지 않는다. 기존 현재 세션만 마지막 방 설정을 사용한다.
- 원본 창 실행은 프로세스와 인자로 확인했다. 운영체제 창 캡처가 실패해 세 공급사 네이티브 화면 전체를 스크린샷으로 검수하지는 못했다.
- 32명의 동시 추론 부하, 장시간 실행, 화면 낭독기, 다른 운영체제의 실행은 확인하지 않았다. Codex `ultra`는 목록 정보와 `exec`의 실제 지원을 구분해 이번 선택지에서 제외했다.
