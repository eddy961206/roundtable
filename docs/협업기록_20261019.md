# 협업 기록 2026-10-19 — 작업 분배·적대적 리뷰·이미지·요청

roundtable 자신을 써서 roundtable 기능을 만들었다. 오케스트레이터(Claude Code)는 브라우저 화면으로 방을 만들고 지시·결정·통합·검증을 맡았다. 구현과 리뷰는 참가자에게 나눴다.

## 참가자와 분담

| 단계 | 작성 | 적대적 리뷰 |
| --- | --- | --- |
| 설계 토론(작업 분배·리뷰) | Opus 5.5 · GPT-6 Astra · Gemini 4 Argon | — |
| 웹 조사(공급사별 캐시·토큰) | Astra | — |
| P1 리뷰 프로토콜 | Astra | Argon |
| P2 작업 분배 백엔드 | Opus(빌드·테스트는 GPT-6.1 Sol), 후속 수정 Sol·Astra | Argon (2라운드) |
| P3 UI | Argon | Astra (2라운드) |
| Q1 이미지·요청 백엔드 | Astra | Argon (2라운드) |
| Q2 이미지·요청 UI | Argon | Astra (여러 라운드) |
| 오케스트레이터 직접 수정 | Claude | Astra |

리뷰는 계약의 표 형식(번호·심각도·파일:줄·재현 시나리오·확신도)으로 하고, 작성자는 항목별 수용·반박, 리뷰어는 수정 확인을 했다. 중간에 사용자 지시로 Claude 사용을 줄이고 GPT·Gemini 비중을 높였다.

## 실측으로 드러난 것

- **Codex Windows 샌드박스**: elevated 샌드박스 준비 단계가 다른 프로세스가 열어 둔 Codex 런타임 실행 파일의 권한을 바꾸지 못해 셸 명령이 모두 실패했다. `-codex-windows-sandbox unelevated`를 추가했고, 이 모드에서도 작업 폴더 밖 쓰기가 막히는 것을 실측했다. unelevated에서는 Go 빌드 캐시 쓰기가 막혀 참가자가 임시 `GOCACHE`를 썼다.
- **Claude write 모드**: `--permission-mode acceptEdits`라 파일 수정은 되지만 셸 명령은 승인을 요구해 비대화형 실행에서 거부된다. Opus가 빌드·테스트를 못 해서 다른 참가자가 넘겨받았다. Claude에게 셸을 여는 것은 샌드박스 없는 실행이라 보류했다.
- **리뷰 표 라벨**: 첫 종단 실행에서 두 리뷰어가 올바른 0건 표를 냈지만 `[지적]` 라벨이 없어 실패했다. 표를 머리글로 식별하게 바꾸고, 형식 오류는 한 번 되묻게 했다.
- **이름 멘션**: `@Astra`처럼 표시 이름으로 부르면 멘션으로 인식되지 않아 전원에게 전달됐다. 이름 멘션을 추가하고 ID·공급사 우선, 정해진 조사, 공백 이름 제외, 멘션 대상 저장 규칙을 붙였다.
- **스크롤 튐**: 창 전환 시 `visibilitychange`가 목록을 다시 그리며 스크롤이 맨 위로 클램프됐다. 위치 복원과 "맨 아래로" 버튼을 넣었다.
- **종단 확인**: 작업 계획 → 파트 작업 → `WORK:DONE` 제출 → 교차 리뷰 → 자동모드 병합·verify, 이미지 첨부(Codex·agy가 이미지 속 글자를 읽음), 참가자 간 요청 생성·완료, 에이전트 이미지 공유를 실제 CLI로 확인했다. 확인모드 승인과 "지적 → 수정 → 재리뷰" 경로는 단위 테스트로만 확인했다.

## 토큰 절약

- 재개 턴에서 바뀌지 않은 고정 안내문(참가자·공지·규칙)을 다시 보내지 않고 한 줄 알림만 보낸다. 컨텍스트가 줄면(CLI 압축) 다시 보낸다.
- 추론 수준만 바꾸면 세션을 유지한다.
- agy 입력을 명령줄 대신 stdin stream-json으로 보낸다(파일 전달·읽기 도구 왕복 제거).
- 리뷰어는 대화 이력 없이 diff·범위·이전 라운드 구조화 기록만 받는다.

## 남은 것

- Claude write 모드의 셸 실행 허용 여부(사람 결정).
- 첨부 마커 숨김은 같은 이름의 다른 경로 파일을 구분하지 못한다(거절 사유는 system 메시지로 보인다).
- 병합이 끝난 파트의 worktree 자동 정리는 아직 없다.
- 심볼릭 링크 탈출 테스트는 Windows 권한 때문에 건너뛴다.
