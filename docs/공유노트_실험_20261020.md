# 공유 탐색 노트 실험 (2026-10-20)

질문: 수렴 단계에서 좌석들이 같은 코드를 각자 다시 탐색하는 비용을 "공유 탐색 노트"로 줄일 수 있는가. 결론: **효과가 확인되지 않아 적용하지 않는다.**

## 방법

- 과제(2라운드): 1라운드에서 요청 마커 흐름(생성→전달→완료·거절→회신→취소)을 코드로 추적해 위험 2개를 찾는다. 2라운드에서 서로 검토해 상위 3개 합의표를 만든다. 작업 폴더는 매 실행 같은 커밋(`029bb74`)의 새 worktree, 방도 새로 만든다. 별도 포트·데이터의 시험 서버를 썼다.
- 조건
  - A 현재 방식: 추가 지시 없음.
  - B 공유 노트: 1라운드에 확인한 사실을 `.rt-notes.md`에 파일:줄로 덧붙이고, 2라운드에 노트를 먼저 읽고 반박할 때만 코드를 다시 확인한다.
  - C 재사용 지시만: 노트 없이 2라운드에 "다른 좌석이 파일:줄로 인용한 사실은 반박할 때만 다시 확인" 지시.
- 좌석: Sonnet 5.5 medium + GPT-6.1 Sol medium. 순서 ABCCBA(조건당 2회).
- 지표: 가중 입력 = 캐시 안 된 입력 + 캐시 쓰기×1.25 + 캐시 읽기×0.1(가정한 가중치), 출력 토큰, Claude 좌석 비용(USD). 품질은 2라운드 합의표를 읽어 비교했다.

## 결과 (Sonnet medium + Sol medium)

| --- | --- | --- | --- | --- | --- |
| A1 | A | 148k | 25k | 7.9k | $0.222 |

- B는 두 번 모두 A보다 비쌌다(Claude 비용 +14% 안팎). 1라운드에 노트를 쓰는 비용이 들고, 2라운드도 줄지 않았다(노트를 읽는 도구 호출이 추가됨).
- C는 합계가 A보다 작았지만, 1라운드는 A와 지시가 같아서 합계 차이 대부분은 회차 간 편차다(A의 1라운드가 123k와 170k로 갈림). 지시가 영향을 주는 2라운드만 보면 C 25k·17k 대 A 25k·36k로 겹친다. 절감이 있더라도 전체의 6% 안팎이고, 2회로는 편차와 구분할 수 없다.
- 품질: 여섯 실행 모두 파일:줄 근거가 있는 위험 3개를 합의했고 조건 간 차이는 보이지 않았다. 반복해서 나온 위험은 진행 중 요청 취소 후에도 대상 작업이 계속됨, 토론 턴에서 처리한 요청의 요청자 회신 누락, pending으로 남은 요청의 재전달 없음이다.
- 참고(좌석 변경 전, Sonnet high + Astra high, 조건당 1회): A 244k, B 233k, C 215k. 방향은 위와 같지 않아(B가 A보다 쌈) 1회 표본의 편차로 본다.

## 판단

- 미리 정한 적용 기준(2회 모두 뚜렷하게 싸고 품질 유지)을 B·C 모두 넘지 못했다. 안내문·기능은 바꾸지 않는다.
- 이 과제 규모(코드 탐색 2라운드, 두 좌석)에서는 좌석 간 메시지 전달이 아니라 각 좌석의 1라운드 탐색이 비용 대부분이다. 중복 탐색을 줄이려면 수렴 단계가 아니라 탐색 단계의 분업(누가 어느 범위를 볼지)을 다뤄야 하지만, 독립 판단(블라인드·적대적 리뷰)과 부딪치므로 별도 검토가 필요하다.
- 실험에서 반복 지적된 요청 흐름의 위험 3개는 실제 결함 후보다. 수정은 하지 않았다.
