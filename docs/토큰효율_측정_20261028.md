# 토큰 효율 개선 측정 (2026-10-28)

목표는 결과 품질을 유지하면서 roundtable 좌석의 입력 토큰을 줄이는 것이다. 후보마다 같은 과제를 기존 방식과 나란히 돌렸다. 입력·캐시·출력·호출 수·시간과 객관 품질 기준을 비교해 채택 여부를 정했다. 측정 도구는 `tools/token_ab/`에 있다.

## 1. 출발점: 비용이 어디서 나오나

### 오케스트레이터 실측
- 범위: 10-26 12시~10-28 00시 KST에 갱신된 방, 좌석 답 220턴.
- 입력 합계 837.5M 가운데 캐시 읽기가 811.3M(97%)이다. 출력은 3.9M이다.

- 입력이 10M 이상인 18턴이 입력의 38%다.

### Codex 세션 로그 분석 (`tools/token_ab/codex_rollout.py`)

이 표에서 비용 요인 세 가지가 보인다.

- 작업이 바뀌어도 세션을 이어 쓰기 때문에 시작 문맥이 커진다.

- 어떤 지침도 1초를 지시하지 않았다. 모델의 습관이었다.

agy 무거운 방(`8a864d16ac29`)도 확인했다.
- `manage_task status`·`list` 호출이 1,186회 가운데 190회였다.

### T5. 검수 통과 뒤 작성 좌석 헛턴 끄기(`quiet_done`) — 채택 (`4998b0f`)

계기는 10-27~28 운영이다. 검수 좌석이 `[[REQUEST_DONE]]`으로 통과를 알리면 서버가 요청한 작성 좌석을 다시 불렀다. 작성 좌석은 "승인됐어" 요약만 쓰면서 문맥 전체를 다시 읽었다. 방 `db7aef99e8e4` #24, `8a864d16ac29` #72, `8befb24e5e10` #31에서 그런 턴 하나가 캐시 읽기 59만~67만 토큰이었다(호출 2회, 문맥 30만~34만).

- 변경: 방 설정 `quiet_done`이 켜져 있으면 완료 신호가 요청자를 부르지 않는다. 거절 신호는 그대로 부른다. 요청을 받은 좌석의 프롬프트에 "이어서 할 일이 있으면 `[[REQUEST:@요청자]]`로 따로 요청"을 붙인다.
- 과제: `tools/token_ab/README.md`에 `turns.py` 절을 추가하고 커밋한 뒤 검수 요청. 방 메모는 `docs/AGENT_GUIDE.md` 6.2의 협업 규칙이다.
- 좌석: 작성 Claude `claude-opus-5-5` high, 검수 agy `gemini-3.8-flash` high. 방마다 작성 1·검수 1, write 모드.
- 작업 사본: roundtable `357bc59`를 꺼낸 worktree. 서버는 `61aeb9e` 빌드를 별도 데이터 폴더로 18797에 띄웠다. 네 방을 같은 시각(10-28 12:09 KST)에 돌렸다.

| 쪽 | 방 입력 합 | 턴 | 작성 좌석 추가 턴(검수 통과 뒤) | 검수 판정 | 커밋 |
|---|---:|---:|---|---|---|
| A1 기존 | 264,421 | 3 | 입력 42,280 · 출력 277 · 7초 | 통과 | README +16줄 |
| B1 quiet_done | 249,552 | 2 | 없음 | 통과 | README +19줄 |

- 없어진 것은 작성 좌석의 마지막 턴 하나다. 그 턴의 입력은 작성 좌석의 문맥 크기(이번 4.2만~4.4만)와 같았다. 운영 방처럼 문맥이 30만~34만이면 같은 턴이 59만~67만이다.

- 품질: 네 방 모두 검수 판정이 통과였고 커밋 내용(절 구성·근거 줄 번호)이 같은 수준이었다. A2의 추가 턴은 "검수 요약에 코드와 다른 표현이 하나 있다"는 지적을 남겼다. 산출물이 아니라 검수 요약 문구에 대한 말이라 커밋은 바뀌지 않았다. quiet_done이면 이런 덧붙임은 나오지 않는다.
- 수정 경로(BF, quiet_done): 검수 좌석에게만 작성 좌석이 모르는 기준을 먼저 주었다. 검수가 "수정 필요"와 `[[REQUEST:@w1]]`을 쓰자 작성 좌석이 그 요청으로 깨어났다(완료 신호로 깨어난 것이 아님). 작성 좌석은 그 기준이 가리킨 문서에 `turns.py`가 없다는 근거로 거절했고, 거절 신호가 검수 좌석을 다시 불렀다. 세 번째 왕복에서 둘 다 "사람 판단"으로 멈췄다. 수정 왕복은 quiet_done에서도 그대로 돈다.
- 미검증: Codex 작성 좌석, 문맥 30만 이상인 실제 운영 방에서의 측정.

### 사용량 경보의 좌석 전달 — 고침 (`4998b0f`)

| 작성·검수 템플릿에 파일:줄·시험 명령을 미리 넣기, 검수에 diff만 주기 | 하지 않음 | 품질 측정에 반복 실행이 많이 필요하다. 검수 템플릿의 변형 실행·반복 실행 요구는 호출을 늘리지만 품질을 위한 것이라 줄이지 않았다. |
