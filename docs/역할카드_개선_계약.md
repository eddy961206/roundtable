# 역할 카드·모델 기록·사용성 개선 계약 (v1)

2026-10-19 설계 방(Fable 5.1·GPT-6.1 Sol·Gemini 4 Argon) 토론과 오케스트레이터 결정을 묶은 구현 계약이다. 세 파트는 이 문서의 이름·JSON 모양을 그대로 쓴다. 바꿔야 하면 구현 전에 방에 알린다.

## 1. 원칙

- **모델 특성을 코드에 고정하지 않는다.** 공급사·모델은 계속 바뀐다. 역할은 좌석 데이터(`Participant.Role`)이고, 추천은 사용자가 편집하는 데이터 파일이다. 실측 기록은 추천의 근거로만 쓰고 자동 배정하지 않는다.
- **강점은 우선순위이지 침묵 사유가 아니다.** 역할 지시문은 "이 관점을 먼저 깊게 보라"이고 "다른 관점의 문제를 말하지 말라"가 아니다.
- 사람이 배정하고, 시스템은 기록하고 추천한다.

## 2. 결정

| 번호 | 결정 |
| --- | --- |
| R1 | `Participant.Role`(문자열, 1~3문장, 비어 있으면 역할 없음). 방 생성의 `participant_specs[].role`, 참가자 수정 PATCH의 `role`로 바꾼다. 역할 변경은 세션을 유지한다(안내문 키가 바뀌어 다음 턴에 고정 안내문이 다시 간다). |
| R2 | 역할은 일반 대화·토론(standingBrief), 파트 작업(BuildPartPrompt), 리뷰어·작성자 리뷰 단계 프롬프트 모두에 들어간다. standingBrief에는 "당신의 역할"과 "다른 참가자들의 역할" 목록이 들어간다(서로의 강점을 알아야 분업·요청이 자연스럽다). |
| R3 | 역할 프리셋과 모델 추천은 서버 데이터 폴더의 `role-presets.json`. 없으면 저장소에 embed한 기본 파일을 복사해 만든다. 사용자는 파일을 직접 고친다(화면 편집은 v2). 서버는 시작 시와 `GET /api/role-presets` 때 읽는다(형식 오류는 즉시 오류로 보여 준다). |
| R4 | 모델 수행 기록은 새 저장소를 만들지 않고 이미 저장된 방 데이터(메시지의 provider·model·effort·role·usage·timing, 작업 계획의 리뷰 결과)에서 계산한다. `GET /api/stats/models`. 추천 표시에는 표본 수와 최근 관측일을 함께 보인다. |
| R5 | 에이전트 턴마다 `Message.Timing`(대기·첫 출력·전체 ms)과 `Message.Role`(그때의 역할)을 기록한다. |
| R6 | CLI 버전: 서버 시작 후 비동기로 각 CLI의 버전 명령을 실행해 캐시한다(시간 제한, 실패는 오류 문자열로). `GET /api/providers`의 각 공급사 정보에 `version`, `version_checked_at`(ms), `version_error`. `POST /api/providers/versions`로 다시 확인한다. |
| R7 | 제목 변경·삭제: 방 머리줄 제목 옆 ✎(클릭·Enter로 인라인 편집, Esc 취소), 방 목록 항목마다 `⋯` 메뉴(이름 바꾸기·삭제·내보내기). 키보드·터치로도 열린다. 삭제는 확인을 거친다. 더보기 메뉴의 기존 항목은 둔다. |
| R8 | 성능: 바뀌지 않은 참가자 상태는 다시 보내지 않는다(서버). 본문이 바뀐 메시지만 Markdown을 다시 변환한다(화면). |
| R9 | 안내문: 재개 턴의 한 줄 알림에 "당신의 역할 한 줄"과 "응답 끝 신호 블록 규칙 한 줄"을 더한다. 리뷰 지시문은 "표만 쓰고, 표를 코드펜스로 감싸지 않는다"로 고치고, 파서는 코드펜스 안이나 일반 문장 속 `|`를 표로 오인하지 않는다. UI를 바꾸는 파트 지시문에는 화면 캡처를 `[[ATTACH]]`로 올리거나 이미지 판독에 강한 좌석에 `[[REQUEST]]`로 시각 검토를 요청하라는 안내를 넣는다. |
| R10 | 미루는 것: 결정 핀, 요약 신호, 진행 상태줄, UI 문체 통일(이번 파트가 끝난 뒤 따로). |

## 3. JSON

```jsonc
// GET /api/role-presets
{
  "presets": [ { "id": "big-picture", "name": "큰 그림·UX", "directive": "…", "tags": ["design", "ux", "intent"] } ],
  "model_suggestions": [ { "match": "claude-*", "preset": "big-picture" } ],  // match: 모델 ID glob, 위에서부터 첫 일치
  "path": "<서버가 읽은 파일 경로>"
}

// GET /api/stats/models  (방 데이터에서 계산)
{
  "rows": [ {
    "provider": "codex", "model": "gpt-6.1-sol", "effort": "high", "role": "<역할 문자열 또는 빈 값>",
    "turns": 12, "errors": 1, "median_total_ms": 41000, "median_first_output_ms": 3500,
    "input_tokens": 0, "output_tokens": 0, "cached_tokens": 0,
    "parts_authored": 2, "parts_passed_first_round": 1,
    "findings_raised": 5, "findings_fixed": 3, "findings_withdrawn": 1,
    "last_seen_at": 1792417324586
  } ],
  "generated_at": 1792417324586
}
```

## 4. 파트 분담

| 파트 | 담당 | 파일 범위 | 리뷰어 |
| --- | --- | --- | --- |
| P1 화면 | Fable | `web/js/` 중 rooms·dialogs·participants·usage·main·layout 모듈, 새 모듈(모델 기록 대화상자), `web/index.html`, `web/style.css` | Sol |
| P2 서버·성능·기록 | Sol | `internal/agent`(버전), `internal/server`(API), `internal/room`의 hub·participants·lifecycle·store·새 stats 파일(prompt.go·review.go·attachments.go 제외), `web/js/timeline.js`(Markdown 재변환만) | Fable |
| P3 안내문·문구 | Argon | `internal/room/prompt.go`, `review.go`, `attachments.go`의 프롬프트 문구, 기본 `role-presets.json`(embed 대상 파일)과 그 문구 | Sol |

공통: fallback·조용한 우회 금지, 계약 위반은 즉시 실패, 공개 레포이므로 내부 회사명·로컬 경로 금지, 커밋은 한국어. web 모듈을 고치면 `python tools/modcheck.py web/js` 0건.
