# 사용성·자원 관리·OpenCode 통합 확인

2026-10-18 KST. 기존 서비스와 데이터 사본을 분리한 로컬 실행 환경에서 확인했다. 테스트 코드와 `go test`는 생성·실행하지 않았다. 32명 동시 호출이나 부하 시험도 하지 않았다.

## 바뀐 사용 흐름

1. **방 만들기**: 공급사를 직접 선택한다. 설치된 CLI를 구독 중인 서비스로 간주하지 않는다. 첫 공급사·모델을 미리 선택하지 않는다. OpenCode 모델은 공급사별 그룹과 검색을 제공한다.
2. **대상 선택과 대화**: 표시 이름으로 참가자를 고른다. 동명이인은 중복 없는 번호를 붙인다. 내부 ID·원본 세션·사용량 상세는 펼쳐서 확인한다. 확인할 수 없는 이름 멘션은 입력창 아래에서 설명하고 전송을 막는다. 코드와 링크의 원문은 이름 치환에서 제외한다.
3. **작업 관리**: 모든 공급사의 카드에 개별 작업 중단을 제공한다. 선택한 참가자의 실행·대기 요청을 취소하고 참여를 끈다. 다른 참가자는 계속 실행한다. 중단 요청 뒤 늦은 HTTP 응답이 최신 SSE 상태를 되돌리지 않게 했다.
4. **사용량 확인**: 선택한 방에 추가한 공급사의 기간별 남은 한도를 좌하단에 고정 표시한다. 참가자를 꺼도 표시를 유지한다. 수동 새로고침과 보이는 탭의 60초 자동 갱신을 제공한다. 새로 확인한 시각과 원래 관측 시각을 구별한다. 지난 초기화 시각만으로 잔여량을 100%로 바꾸지 않는다. 설치 여부는 접힌 상세로 옮겼다. 모바일에서는 사용량 버튼으로 같은 패널을 연다.
5. **기록 탐색**: 최근 100개부터 열고 이전 기록을 페이지로 조회한다. 화면은 최대 200개 메시지와 최대 8개 답변의 작업 기록을 유지한다. 각 작업 기록의 화면 캐시는 200개 이벤트까지다. 전체 내보내기는 보존한다.

실제 화면에서 이름 충돌, 미등록 이름 전송 차단, 공급사 미선택 기본값, 코드 원문 보존, 이전 기록 탐색, 개별 중단을 확인했다. 420×800 화면에서 문서 가로 폭은 420px이고 가로 넘침은 관측되지 않았다. 이는 사용성 원칙에 따른 전문가 검토와 실제 화면 관측이며, 사람 대상 연구나 전체 접근성 적합성 검사는 아니다.

CLI 중단은 연결된 로컬 프로세스와 대기 작업의 종료를 뜻한다. 이미 공급사로 전달된 요청의 서버 측 연산·청구 취소까지 보장하지 않는다. 이미 종료한 Windows 부모 프로세스에서 분리된 후손 프로세스의 정리도 이번 확인 범위에 포함하지 않는다.

## 자원 관리

- 서버 시작 때 전체 작업 기록을 메모리에 올리지 않는다. 답변을 펼칠 때 디스크에서 읽는다.
- 작업 기록 저장과 전체 내보내기 형식을 만드는 작업을 방 전체 잠금 밖에서 수행한다.
- 이벤트 저장 순번을 사용해 조회 중 들어온 실시간 이벤트를 병합한다. 느린 SSE 소비자는 연결을 닫고 다시 동기화하게 한다.
- 사용량 조회는 공급사별 동시 요청을 합치고 20초 제한을 둔다. 서버 전체의 무조건적인 정기 조회는 없다.
- OpenCode 모델 목록은 성공 시 10분 캐시하고, 사용자가 연결·모델 새로고침을 누르면 다시 읽는다. 모델 조회가 방 전체 잠금을 잡지 않는다.
- stderr 보관은 64KiB로 제한한다. 출력 읽기 오류와 취소 때 파이프를 닫아 무기한 대기를 막는다. 서버 종료 때 실행·대기·사용량 저장 작업을 정리한다.

**남은 용량 특성**: 서버 메시지 본문과 디스크 JSONL은 누적된다. 전체 내보내기와 한 답변의 전체 작업 기록 조회는 일시적으로 그 자료를 메모리에 올린다. 이번 변경은 장시간·대규모 사용에서 메모리가 일정하다는 보장이 아니다. 동일 조건의 성능 비교나 장시간 관찰을 하지 않았으므로 성능 개선 비율을 제시하지 않는다.

## 계정과 OpenCode Go

Roundtable은 OpenCode의 공식 CLI와 연결된 공급사 목록을 사용한다. API 키를 직접 읽거나 복사하지 않는다. 작업 전후 OpenCode 설정 파일의 SHA-256이 같았다. 계정별 구독 여부를 설치 여부로 추정하지 않는다.

[OpenCode Go 공식 문서](https://opencode.ai/v2/docs/console/go/)는 Go를 다른 OpenCode 공급사와 같은 방식으로 연결한다고 설명한다. 구독 후 OpenCode에서 연결하고 Roundtable의 연결·모델 새로고침을 누르면 해당 모델을 선택하는 구조다. 실제 Go 구독 계정은 없으므로 Go 호출과 한도 조회는 미검증이다. OpenCode의 구독 한도와 API 잔액은 현재 화면에 조회 미지원으로 표시한다. 토큰과 CLI 보고 비용을 실제 청구액으로 간주하지 않는다.

[CLI 문서](https://opencode.ai/v2/docs/cli), [권한 문서](https://opencode.ai/v2/docs/permissions), [공급사 문서](https://opencode.ai/v2/docs/providers)를 설치된 v2 CLI 동작과 대조했다. 과거 v1의 설정·권한 형식을 그대로 적용하지 않았다.
