### 추가 조사 — agy 재개 턴과 추론 수준 변경 (같은 날)

agy 명령을 입력 기록용 중계 프로그램으로 바꿔(`-agy` 옵션) 두 버전이 실제로 보낸 인자와 입력을 턴마다 남기고, Argon 한 자리로 8턴 시나리오를 동시에 다시 돌렸다(3회차, `turns.py ... short argon`). agy CLI도 직접 실행해 입력 경로만 바꿔 비교했다.

| 항목 | 이전 | 현재 |
|---|---|---|
| roundtable이 보낸 재개 턴 프롬프트 | 약 3,030바이트 | 약 640바이트 (**−79%**) |
| 3회차 재개 턴 3~6 비캐시 입력 | 3,837 / 3,848 / 3,833 / 3,835 | 2,390 / 2,419 / 2,363 / 2,360 (**−38%**) |
| 추론 수준 변경 직후 턴 비캐시 입력 | 16,170 (새 세션) | 22,992 (세션 유지, 캐시 없음) |

확인한 사실:
1. **입력 경로는 토큰에 영향이 없다.** gemini-3.8-flash에 같은 질문을 명령줄(`-p=`)과 stdin stream-json으로 보냈을 때 세 턴의 입력이 14,831 → 15,835 → 16,839로 똑같았다.
2. **agy가 재개 턴마다 약 1,000토큰을 스스로 붙인다.** "2+2? 숫자만." 같은 짧은 문답에서도 턴마다 입력이 1,004토큰씩 늘었다. Argon 수정 빌드에서도 문맥이 턴당 약 1,255토큰 늘었는데, roundtable 프롬프트(약 200토큰)와 직전 답(약 105토큰)을 빼면 나머지가 agy 몫이다. roundtable이 줄일 수 없는 부분이다.
3. **2회차의 +35%는 서버 캐시 편차였다.** 같은 이전 버전이 같은 크기의 프롬프트를 보냈는데 재개 턴 비캐시 입력이 2회차 약 2,080, 3회차 약 3,840으로 1.8배 달랐다. 프롬프트를 기록한 3회차에서는 현재 버전이 38% 적었다.
4. **추론 수준을 바꾸면 Gemini 캐시가 무효가 된다.** 세션을 유지해도 그 턴은 전체 문맥을 비캐시로 다시 읽는다. Claude는 같은 상황에서 캐시를 유지했다.

추론 수준 변경 정책은 바꾸지 않았다. 세션 유지 비용은 그 시점 문맥을 한 번 비캐시로 읽는 것이다. 새 세션은 안내문과 최근 기록(60KB·40개 한도)만 보내 더 적을 수 있지만, agy가 그 세션에서 읽은 파일·도구 결과를 잃는다. 추론 수준 변경은 사람이 가끔 하는 조작이라 한 번의 비용보다 문맥 유지를 택했다.

조사 중 찾아 고친 버그 (모두 회귀 테스트 추가):
- **agy 사용량 이중 집계**: agy의 `result.usage`는 그 대화 전체 누적값인데 턴 사용량으로 저장했다. 그래서 답변별 사용량, 참가자 누적, `/api/stats/models`가 agy 토큰을 크게 부풀렸다. 3회차 8턴 기준 저장된 입력 합은 237,394였지만 실제 턴별 합은 약 54,000이었다(4.4배). 이제 이번 실행의 단계(step)별 사용량을 더해 기록한다.
- **agy 문맥 크기 오독**: 마지막 단계의 비캐시 입력만 `context_tokens`로 써서 문맥 표시가 실제(약 2만)보다 훨씬 작은 2~3천으로 나왔다. 이제 마지막 단계의 비캐시 입력과 캐시 입력을 더한다.
- **압축 감지가 동작하지 않음 (공급사 공통)**: 문맥이 줄면(CLI 압축) 다음 턴에 안내문을 다시 보내도록 표시를 지웠지만, 턴이 끝날 때 그 표시를 다시 덮어썼다. 이제 압축이 감지된 턴은 끝난 뒤에도 표시를 지운 상태로 둔다.

## 결과 4 — Codex (Astra): 큰 누수를 찾아 고친 뒤 −40%

| 추론 수준 변경 직후 턴 | 2,041 (새 세션, 비캐시 1,017) | 3,536 (세션 유지, 비캐시 464·캐시 3,072) |

- 이 공급사는 추론 수준을 바꿔도 캐시를 유지했다. 그래서 세션 유지가 그 턴의 비캐시 입력도 줄였다(1,017 → 464).
- 이전 버전은 재개 턴마다 안내문을 다시 보내 비캐시 입력이 턴당 약 1,100이었다. 현재는 약 430이다.

## 사용량 기록 점검 — Claude 비용·OpenCode 문맥·과거 기록 보정

공급사별 사용량이 "이번 턴" 값으로 저장되는지 마지막으로 점검했다.

| 공급사 | 문제 | 수정 |
|---|---|---|
| agy | 토큰이 대화 전체 누적값 | 단계별 합 (`0ff0034`) |
| Codex | 토큰이 스레드 전체 누적값 | rollout의 턴 시작 전 누적값을 뺌 (`a8e35bf`) |
| Claude | 토큰은 턴 값이 맞지만 `total_cost_usd`가 세션 누적 비용. Haiku 재개 3턴 실측 0.0038 → 0.0070 → 0.0084 | CLI 값은 `session_cost_usd`로 보관하고, 같은 세션의 직전 값을 빼서 `total_cost_usd`(이번 턴 비용)를 만든다 |
| OpenCode | 토큰은 턴 값이 맞지만 문맥 크기를 캐시 제외 입력으로 잡음(1027, 197, 725, 279). 문맥이 줄어든 것처럼 보여 압축 감지가 잘못 켜지고 한 턴 걸러 안내문 전체를 다시 보냄 | 문맥 = 입력 + 캐시 읽기 + 캐시 쓰기. 수정 후 1,230 → 1,496 → 1,762 → 2,028로 단조 증가, 재개 턴 입력 약 350 유지 |

이미 저장된 기록은 `tools/fix_cumulative_usage.py`로 한 번 보정했다(서버 정지, 방 폴더 전체 백업 후). 같은 세션 안의 직전 답변과의 차이로 턴 값을 다시 계산하고, 참가자 누적값도 다시 더했다. 값이 줄어든 세션이 하나도 없어 누적값이라는 가정과 맞았다.

## 측정 한계

- 회차가 2회뿐이다. Opus 결과는 두 회차 방향과 크기가 일치하지만, Argon은 회차 사이 편차(이전 버전 재개 턴 2,080 대 4,050)가 효과 크기보다 크다.
- OpenCode는 무료 모델 하나로 1회만 쟀다. 다른 OpenCode 공급사는 캐시 동작이 다를 수 있다.
- Codex는 1회만 쟀다. 효과(−40%)가 스킬 목록 재주입이라는 확인된 원인과 맞지만, 재주입 빈도는 사용자 플러그인 구성에 따라 다를 수 있다.
- 비용은 CLI가 보고한 `total_cost_usd`이며 구독 한도 소모량과 같다고 확인하지 않았다.
- agy 한도가 캐시 입력을 얼마로 세는지 확인하지 않았다. 그래서 Argon은 비캐시와 전체 처리량을 함께 적었다.

## 다시 재는 법

1. 비교할 두 커밋을 각각 빌드한다(이전 커밋은 `git worktree add --detach`로 받는다).
2. 두 바이너리를 다른 포트와 다른 `-data` 폴더로 띄운다.
3. 두 서버에 `python tools/token_ab/turns.py <주소> <이름> <결과.json> short`를 동시에 실행한다. 자리는 `opus`, `argon`, `astra` 중 원하는 것을 덧붙여 고른다(생략하면 Opus·Argon).
4. `python tools/token_ab/summarize.py <이전.json> <현재.json>`으로 비교한다. 사용량 수정 이전 빌드(agy는 `1c5a9d9`, Codex는 `298216b`까지)의 결과는 대화 누적값이므로 파일 이름 뒤에 `@cumulative`를 붙인다.
5. 긴 입력은 `python tools/token_ab/long_input.py <주소> <이름> <결과.json> 3`으로 잰다.
