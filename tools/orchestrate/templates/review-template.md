병합 전 검수야. 작성에 참여하지 않은 별도 문맥 검수야. 소스·문서는 고치지 말고 커밋·게시도 하지 마. 다만 프로젝트의 정적 검사·전체 시험은 직접 실행해(시험이 만드는 임시 파일·빌드 캐시는 괜찮아). 작성자의 통과 보고를 그대로 믿지 말고 직접 돌린 결과로 판단해.

## 대상
- 작업 폴더(worktree)의 현재 브랜치. 검수 범위는 `git diff origin/main...HEAD`.
- 기준 문서: (프로젝트의 결정 기록·계약 문서·작업 규칙을 여기에 적는다). 작업 기록은 브랜치의 새 작업 기록 파일.

## 확인할 것 (구체적 실패 조건이 있는 것만)
1. 결정·계약이 요구한 동작이 빠졌거나 약해진 곳. 검사가 그 동작을 실제로 검증하는지(반례가 기준 브랜치에서 실패하는 시험인지).
2. 기준 대비 회귀: 기준이 하던 정상 동작을 이유 없이 잃은 곳.
3. 정확성·동시성·자원 누수·오류 처리 결함(경합, 취소 누락, 무한 버퍼, 파일 핸들, 트랜잭션 경계).
4. 다른 모듈 공개 API를 계약과 다르게 쓴 곳. 범위 밖 모듈을 바꾼 곳.
5. 문서·작업 기록이 코드와 다른 곳.
6. 직접 실행한 검사 명령과 결과를 적어.

## 반드시 직접 할 것
7. **가드 변형**: diff의 새 가드(조건식·쿼리 조건·오류 반환·잠금·범위 검사)를 하나씩 변형(조건 제거·비교 반전·오류→성공·상수 축소)해 시험이 잡는지 실제로 돌려. 원본은 바꾸지 말고 변형 실행 기능을 써. 살아남은 변형은 막는 문제로 적어.
8. **기준 대비 회귀**: 작성자 반례 시험을 기준 브랜치에 옮겨 실패하는지 확인하고, 네가 만든 임시 입력을 기준과 브랜치에 함께 돌려 나빠진 입력을 찾아.
9. **과잉 대응·조용한 폐기**: 정지·Close·연결 종료·전체 거부 경로마다 "일시적 입력 하나로 여기 오는가", 폐기 경로마다 "공백 표시나 오류 이벤트가 남는가"를 확인해.
10. **풀리지 않는 상태**: 새 플래그·대기열·커서가 풀리는 경로와 해제 주체를 찾고, "이상 1회 → 정상 입력 계속"으로 복귀하는지 봐.
11. **시계**: 시각을 다루면 역행·전진 점프·재기동을 넣어 봐. 짝을 이루는 쿼리(열기/이어 읽기, 페이지/경계)의 조건이 같은지 봐.
12. **간헐성·겹침**: 새 시험은 20회 이상 반복하고, 같은 파일·스키마 번호를 건드리는 열린 PR이 있으면 작업 기록에 적혔는지 봐.
13. 계약 문장을 실행 결과와 대조하고, 작업 기록에 로컬 절대 경로가 없는지 봐.
