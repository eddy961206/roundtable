## 작성 공통 규칙
- 새 가드·조건·오류 경로마다 그것을 지우면 실패하는 시험을 둔다. 원본을 바꾸지 않는 변형 실행(예: Go `go test -overlay`)으로 확인하고, 작업 기록·PR 본문에 "가드 → 잡는 시험" 표와 변형 결과(검출/전체)를 적는다. 오류는 개수가 아니라 종류로 단언한다.
- 반례 시험과 기존 경계 입력을 기준 브랜치에서도 돌려 "입력 | 기준 | 브랜치 | 의도" 표를 붙인다. 의도라고 적지 않은 차이는 회귀다.
- 오류마다 영향 범위를 정해 가장 좁게 처리한다. 정지·연결 종료·전체 거부는 근거 문서를 인용한다. 버리는 데이터는 공백 표시나 오류 이벤트로 남긴다.
- 새 상태·플래그·대기열은 진입·해제 조건과 해제 주체를 적고, "이상 1회 → 정상 입력 계속" 회복 시험을 둔다.
- 시각을 다루면 역행·전진 점프·재기동 시나리오를 돌린다. 기한·상한은 포함 구간과 현실 최댓값 입력의 결과를 적는다.
- 새 동시성 시험은 20회 이상 반복해 간헐 실패가 없음을 확인한다.
- 문서 동작 문장마다 확인 시험 이름을 붙이고, 확인하지 않은 것을 완료로 쓰지 않는다. 같은 파일·문서 절·스키마 번호를 건드리는 열린 PR을 작업 기록에 적는다.
- 작업 기록·커밋에 로컬 절대 경로를 남기지 않는다. PR 본문 초안은 커밋하지 않는다.
- 하위 에이전트(자체 분리 검수)는 쓰지 않는다. 다른 공급사 검수는 오케스트레이터가 붙인다. 로컬 커밋까지만 하고 push·PR은 하지 않는다.
